# i18n Audit — 2026-05-12

## Critical findings

1. Landing copy drift existed between locales.
- `/Users/Shared/Projects/habigoal/messages/en.json` still contained the outdated English subtitle while Hungarian had already been updated.

2. News locale behavior was fail-open.
- `/Users/Shared/Projects/habigoal/lib/news.ts` previously fell back to English or any available translation.
- Result: a post written in one language appeared in other locales.

3. Onboarding UI shipped with hardcoded English fallback text.
- `/Users/Shared/Projects/habigoal/components/onboarding/OnboardingModuleCard.tsx`
- `/Users/Shared/Projects/habigoal/components/onboarding/OnboardingChecklistCard.tsx`

## Medium findings

1. Showcase seed content still contains embedded English prose.
- `/Users/Shared/Projects/habigoal/scripts/seed-showcase-athletes.mjs`
- This is demo data, but it still leaks language-specific text into reports and athlete surfaces.

2. Message catalog quality is inconsistent across locales.
- Some non-English files still contain English strings.
- This is a translation-quality problem, not just a missing-key problem.

## Remediation plan

### Phase 1: Make i18n fail closed
- Never fall back across languages for public content.
- Render or list a post only when the requested locale has complete content.
- Add CI checks for missing locale keys in message files and localized content.

### Phase 2: Eliminate hardcoded UI strings
- Move all user-facing component fallback strings into message catalogs.
- Audit `app/`, `components/`, and `lib/` for inline labels, placeholders, button text, and descriptions.

### Phase 3: Canonical language governance
- Treat English as the canonical source language.
- Require every new feature to land with English copy first.
- Allow other locales only when their catalogs are explicitly reviewed.

### Phase 4: Automated enforcement
- Add a repository script that scans for likely user-facing hardcoded strings in TS/TSX.
- Add a locale coverage check for `content/news/posts.json`.
- Block PRs when new public UI strings bypass the message catalog.

### Phase 5: Content workflow
- Store per-post locale availability explicitly.
- Generate weekly news posts in English first, then add other locales deliberately rather than by fallback.
