# i18n Audit

Initial audit date: 2026-05-12

Last documentation update: 2026-05-20

## Current Rules

- User-facing application copy belongs in `/messages`.
- Public news posts render only when the requested locale exists in `content/news/posts.json`.
- Legal pages must be public and localized.
- RTL locales `ar` and `he` require explicit layout checks for action bars, buttons, charts, and report views.
- No shared component should include hardcoded English fallback copy for visible UI.

## Issues Already Addressed

- Landing page English subtitle drift was corrected.
- News locale behavior was changed from fail-open fallback to exact-locale rendering.
- Visible mixed-language report and record action labels were corrected in Hebrew, Spanish, and German.
- Settings governance labels were moved into message catalogs.
- Footer/legal labels were corrected in several locale files.

## Known Remaining Risk Areas

- Some athlete-management form labels still exist as inline copy.
- Some daily check-in support/summary labels still exist as inline copy on `main`.
- Demo/showcase seed content can contain English prose by design and may appear in generated demo reports.
- Older branch work may contain better i18n structure than `main`; only merged code should be documented as shipped.

## Release Gate

Before a production release that touches UI copy:

```bash
npm run i18n:audit
npm run build
```

The audit blocks releases when locale catalogs drift from `messages/en.json`, ICU placeholders do not match, public news content is only partially localized, or known legacy copy leaks appear in app code.

Then manually check at least:

- `/en`
- `/hu`
- `/he/dashboard/records/[id]`
- `/es/dashboard/settings`
- `/ar/dashboard`
- `/en/news`

## Remediation Plan

### Phase 1: Continue hardcoded-string cleanup

- Move remaining athlete-management copy into `/messages`.
- Move remaining daily check-in labels into `/messages` or centralized form definitions once merged.
- Remove hardcoded accessibility labels from shared components.

### Phase 2: Add enforcement

- Maintain `npm run i18n:audit` on `main`.
- Keep the automated gate focused on objective failures: catalog key parity, placeholder parity, partial news localization, and known legacy copy leaks.
- Treat broader translation quality as a manual review until a stronger translation QA workflow exists.

### Phase 3: Centralize forms

- Move form labels, help text, visibility rules, and validation into shared definitions.
- Use page adapters only for route-specific submit behavior.
- Keep onboarding targets tied to stable field ids.

### Phase 4: Content workflow

- Generate weekly news in English first.
- Add other locales deliberately.
- Do not expose a post in a locale until that locale content exists.
